# 名詞解釋

這個專案的文件都會用到下面這些詞。每份文件第一次用到時會簡短解釋，完整說明在這裡。

## 硬體與框架

- **Neural Engine（ANE）**：Apple 晶片裡專門跑 AI 模型的單元，和 CPU、GPU 是三個不同的東西。特點是耗電低，但記憶體頻寬比 GPU 小很多，所以跑大模型不一定比 GPU 快。
- **Core ML**：Apple 的模型執行框架。模型要先轉成 Core ML 格式，才有機會被排到 Neural Engine 上執行。轉成 Core ML 不代表真的跑在 Neural Engine 上，實際位置要用工具量。
- **MLX / MLX-Audio**：Apple 的另一套機器學習框架，跑在 GPU 上。本專案拿它當「GPU 路線」的對照組。
- **MPS**：PyTorch 在 Apple GPU 上的後端。官方 Qwen3-ASR 程式碼可以用它跑，也是對照組之一。
- **Instruments**：Xcode 附的效能分析工具。本專案用它錄下 Neural Engine 和 GPU 真正在忙的時間段，作為「模型真的跑在 Neural Engine 上」的證據。
- **MLComputePlan**：Core ML 的 API，回報「編譯器打算把每個運算放到哪個裝置」。這只是計畫，不是實際執行紀錄。

## 模型與檔案

- **Qwen3-ASR 1.7B**：阿里巴巴開源的語音辨識模型，17 億參數。本專案把它移植到 Neural Engine。
- **0.6B 模型**：同系列的小版本，6 億參數。只用在「推測解碼」實驗裡當猜字的小模型。
- **編碼器（encoder）**：模型裡把聲音變成特徵的部分。
- **解碼器（decoder）**：模型裡一個字一個字產生文字的部分，共 28 層。語音辨識大部分時間花在這裡。
- **bundle（模型包）**：一組轉換好的 Core ML 模型檔案，放在 `artifacts/` 底下。一個 bundle 包含編碼器、解碼器、以及輸出層。
- **partition（分段）**：解碼器 28 層被切成幾個 Core ML 檔案。原本切成 7 個檔案、每個 4 層；現在預設切成 2 個檔案、每個 14 層（文件裡有時簡稱 p14）。檔案越少，每產生一個字要呼叫系統的次數越少。
- **FP16**：原始精度、未壓縮的權重，每個數字佔 16 位元。本專案的第一個可用版本就是 FP16 版，所有「快 30%」「省 27%」都是和它比。
- **8-bit 壓縮版（技術名稱 LUT8 g32）**：權重用查表法壓成 8 位元，每 32 個輸出通道共用一張表。檔案比 FP16 小一半，速度快約 30%，品質量不出差別。這是現在的預設。
- **4-bit 壓縮版（LUT4 g16）**：同樣方法壓成 4 位元。檔案更小，但速度和 8-bit 一樣，品質變差，所以沒採用。
- **16 字圖（T16）**：解碼器一次處理 16 個字的版本。開頭吃提示時用得到；逐字產生時只有 1 列有效，其他 15 列浪費。「1 字圖（T1）」是一次只處理 1 個字的版本。
- **KV cache（快取）**：解碼器記住前面內容的記憶體。本專案固定 1024 格，對應最長 30 秒音訊。

## 量測

- **實際耗時**：從開始到結束真正過了多少秒。舊的實驗紀錄裡寫的「牆鐘」就是這個意思；新文件改用「實際耗時」。
- **RTF**：處理時間除以音訊長度。0.1 表示 10 秒的錄音花 1 秒處理。
- **WER / CER**：錯誤率。英文按詞算（WER），中文按字算（CER）。越低越好。
- **pp（百分點）**：兩個百分比相減的單位。錯誤率從 2.0% 變 2.3% 是 +0.3 pp。
- **測試錄音（smoke）**：Qwen 官方提供的兩段錄音，英文 15 秒、中文 4 秒。速度和耗電都拿這兩段反覆跑。
- **挑選集（selection set）**：英文 100 句（LibriSpeech）加中文 100 句（FLEURS）。用來在候選方案之間做選擇。
- **驗證集（held-out set）**：另外 200 句，從來沒用來挑方案，只對最後選定的方案跑一次。
- **配對比較 / 信賴區間**：同一句話讓兩個版本各辨識一次再比。信賴區間（CI）是用重抽樣估的誤差範圍。
- **等工作量 ABBA**：量耗電時，兩個版本各跑一樣多的音訊，順序 A、B、B、A 交替，避免先跑或後跑造成偏差。
- **整機功率估計（PSTR）**：Mac 的電源管理晶片回報的整台機器功率，約每秒一筆。不是插座上的電表，也分不出哪個零件耗了多少。更精確的 `powermetrics` 需要管理員密碼，本專案沒拿到。
- **常駐記憶體（wired）**：作業系統釘住、不能換出到磁碟的記憶體。Neural Engine 的模型權重算在這裡，不算在 Python 程序的記憶體裡，所以看程序記憶體會低估。
- **Neural Engine 忙碌占比**：Instruments 錄到的 Neural Engine 工作時間段，除以辨識的實際耗時。這是「時間占比」，不是計算量占比或耗電占比。

## 演算法

- **貪婪解碼（greedy）**：每一步都選機率最高的字。本專案所有量測都用這個設定。
- **推測解碼（speculative decoding）**：小模型（0.6B）先猜接下來十幾個字，大模型（1.7B）一次驗證，只保留猜對的前綴。結果和大模型自己逐字算完全一樣，只是快。本專案的實驗版是小模型在 GPU 上猜、大模型在 Neural Engine 上驗證。
- **接受率**：推測解碼裡小模型猜的字有多少比例被大模型接受。越高越省時間。

## 協議

- **Standard ASR**：一套語音辨識引擎的共同介面規範，現在是 0.2 版。本專案是它的一個外掛（plugin）。
- **compliance run**：Standard ASR 附的檢查指令，確認外掛的介面符合規範。它不載入模型，模型檔不存在也會通過。
- **串流（streaming）**：邊錄邊辨識，先給暫定結果，錄完再給定稿。
